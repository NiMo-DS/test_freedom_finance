# Data Analysis Tool (Streamlit)

Небольшое интерактивное веб-приложение для быстрого анализа и изучения табличных данных (CSV и Excel). 

Сделано как внутренний инструмент для аналитиков: загрузил файл, быстро отфильтровал нужные строки, посмотрел графики и группировки, выгрузил готовый результат.

---

## Что умеет приложение

- Загрузка файлов: принимает `.csv`, `.xlsx` и `.xls`.
- Быстрый обзор: сразу показывает количество строк, колонок и сколько всего пропусков в данных.
- Фильтры и сортировка: в боковом меню можно отфильтровать данные по категориям или числовым диапазонам, а также отсортировать таблицу.
- Группировка: можно сгруппировать данные по выбранной категории и посчитать сумму, среднее, минимум, максимум или количество.
- Топ / Bottom: быстрая выборка N лучших и худших записей по любой числовой колонке.
- Графики: строит интерактивные графики на Plotly (динамика по датам или гистограмма распределения).
- Авто-инсайты: простые текстовые подсказки о качестве данных (пропуски, преобладающие категории, разброс).
- Экспорт: отфильтрованный срез данных можно сразу скачать обратно в CSV или Excel.

## Для удобства проверки проект можно запустить двумя способами:
1. Локальный запуск - прямое исполнение в Python-среде (требует предварительной установки зависимостей).
2. Docker-контейнер - полностью изолированный запуск одной командой (рекомендуемый способ, не требует локальной установки Python и библиотек).

### Вариант 1. Локальный запуск

1. Клонируем репозиторий:
   ```bash
   git clone https://github.com/NiMo-DS/test_freedom_finance.git
   cd test_freedom_finance
   ```

2. Создаём и активируем виртуальное окружение:

   *Для Windows (CMD):*
   ```cmd
   python -m venv .venv
   .venv\Scripts\activate.bat
   ```

   *Для macOS / Linux:*
   ```bash
   python -m venv .venv
   source .venv/bin/activate
   ```

3. Устанавливаем зависимости:
   ```bash
   pip install -r requirements.txt
   ```

4. Запускаем Streamlit:
   ```bash
   streamlit run app.py
   ```

Приложение откроется в браузере по адресу `http://localhost:8501`

### Вариант 2. Запуск через Docker (изолированный)

1. Убедитесь, что у вас запущен Docker и установлен Docker Compose.
2. Клонируйте репозиторий и перейдите в папку проекта (если не сделали этого ранее):
   ```bash
   git clone https://github.com/NiMo-DS/test_freedom_finance.git
   cd test_freedom_finance
   ```
3. Соберите и запустите контейнер:
   ```bash
   docker compose up --build
   ```

   ПРИМЕЧАНИЕ: Если порт 8501 у вас уже занят другим сервисом (тестовым другого кандидата), вы можете переопределить его при запуске, например: 

   - *Linux / macOS / Git Bash:*
     ```bash
     PORT=8502 docker compose up --build
     ```
   - *Windows (PowerShell):*
     ```powershell
     $env:PORT=8502; docker compose up --build
     ```
   - *Windows (CMD):*
     ```cmd
     set PORT=8502&& docker compose up --build
     ```

4. Перейдите в браузере по адресу: `http://localhost:8501` (или по указанному вами порту).
5. Для остановки контейнера нажмите `Ctrl + C` или выполните команду:
   ```bash
   docker compose down
   ```

## Ограничения

### По архитектуре 

- Pandas грузит всё целиком в оперативку. На небольших файлах всё работает быстро, но если закинуть очень большой файл (упирается в оператику), всё начнет сильно лагать или просто упадет по памяти.
- В Streamlit любой клик по фильтру перезапускает скрипт сверху вниз. Если файл большой, фильтрация при каждом движении слайдера будет ощутимо подтормаживать.
- Если загрузить кривую Excel с объединенными шапками или пустой файл, приложение покажет стандартную ошибку Python вместо понятного предупреждения. Исключения на импорт.
- Нет сохранения сессии. Если случайно обновить страницу, всё слетит: и загруженный файл, и выставленные фильтры.
- Тут нет логинов, паролей, ролевой модели.
- Если развернуть это на сервере и туда одновременно зайдут 10 человек с крупными файлами, сервер быстро останется без памяти. 
- Нет разделения на фронтенд и бэкенд. (плохоя безопасность, риск зависаний)

### По продукту для стратегов

- Функция экспорта отдаёт только отфильтрованную сырую таблицу. Сгенерированные графики, ключевые цифры и выводы остаются заперты в интерфейсе, из-за чего пользователю приходится вручную делать скриншоты для презентаций.
- Нет сохранения гипотез и совместной работы. При перезагрузке страницы или смене настроек сбрасывается весь контекст. Нельзя сохранить удачный срез данных, сделать закладку или поделиться ссылкой на конкретный график с коллегами.
- Инструмент никак не подсвечивает аномалии, пропуски или полноту загруженных данных. Стратег может принять решение на основе неполной выборки, не зная о скрытых ошибках в исходном файле.

## Что можно доработать 

### По архитектуре

- Разделить Frontend и Backend. Тяжелые расчеты не должны крутиться внутри Streamlit. Логику нужно вынести в отдельное API (например, FastAPI), чтобы UI отвечал только за отрисовку и не зависал при вычислениях.
- Изоляция и безопасность недостаточные. Прямое подключение UI к базе - это дыра в безопасности, в т.ч. от сотрудников. Любая уязвимость в интерфейсе дает прямой доступ к данным. Базу нужно спрятать за API, которое будет строго проверять входящие запросы.
- Для API нужно создать отдельного пользователя в SQL с минимальными правами. Ему разрешают только чтение и только из конкретных нужных таблиц, чтобы исключить случайное удаление или утечку данных.
- В идеальной архитектуре вместо передачи крупных файлов через интерфейс предпочтительнее использовать прямое подключение к базе данных (PostgreSQL/ClickHouse) или Data Lake (S3). Однако если сохраняется сценарий с загрузкой файлов пользователем, важно предусмотреть оптимизацию под большие эксель файлы: сохранять входящий поток во временный файл на диск сервера и использовать ленивую обработку через Polars. Это защитит сервер от ошибок нехватки памяти без усложнения инфраструктуры.
- При сохранении сценария с файлами стоит добавить кэширование повторных вычислений (`st.cache_data`, чтобы не пересчитывать агрегаты при каждом клике) и обработку/выдачу данных частями (чанкинг), защитив интерфейс Streamlit от зависаний при переключении фильтров.

### По продукту для стратегов

- Внедрить полноценный экспорт отчетов. Вместо скачивания изменённых таблиц добавить возможность выгрузки сгенерированных графиков и одной кнопкой формировать итоговый PDF-отчет с ключевыми метриками и графиками для презентаций.
- Реализовать сохранение состояния дашборда (наборов фильтров и гипотез) в профиле пользователя или через генерацию уникальной URL-ссылки, чтобы стратеги могли делиться инсайтами с коллегами.
- Добавить блок индикации качества исходного файла: подсвечивать пропущенные значения, дубликаты и аномальные выбросы до начала анализа, защищая пользователей от выводов на некорректных данных.
